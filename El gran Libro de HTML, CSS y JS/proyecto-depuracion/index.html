Tema 6.6.1

Introducción a la Depuración

Comprender qué es un error, por qué ocurre y cómo abordarlo metódicamente es la habilidad fundamental de todo desarrollador web.

🔍 ¿Qué es la Depuración (Debugging)?

La depuración es el proceso metódico de identificar, analizar y eliminar fallos (bugs) en el código. No se trata de adivinar, sino de formular hipótesis, inspeccionar variables y verificar el flujo de ejecución paso a paso.

En JavaScript, un entorno interpretado y dinámico, un error no detectado puede detener por completo la ejecución de un script o generar comportamientos inesperados en la interfaz de usuario.

🧠 La Paciencia como Virtud Técnica

Depurar requiere calma y rigor deductivo. Cuando un script falla, el intérprete de JavaScript suele darnos pistas exactas: el tipo de error, el archivo y la línea exacta donde la ejecución no pudo continuar.

Aprender a leer estas pistas con serenidad ahorra horas de frustración y convierte el error en una oportunidad didáctica.

Clasificación de Errores en JavaScript

1. Errores de Programación

Ocurren por infringir las reglas sintácticas del lenguaje o invocar identificadores inexistentes.

  • SyntaxError: Paréntesis sin cerrar, palabras reservadas mal escritas.
  • ReferenceError: Usar una variable o función no declarada.
  • TypeError: Llamar a algo que no es función o acceder a propiedades de null/undefined.

2. Errores Lógicos

El código es sintácticamente impecable y el navegador lo ejecuta sin arrojar alertas rojas, pero el resultado del cálculo o del flujo es incorrecto.

  • Bucles infinitos o condiciones fuera por uno (off-by-one).
  • Inversión de condiciones booleanas (> en lugar de <).
  • Operaciones matemáticas con tipos mixtos (ej. "5" + 2 = "52").

3. Errores Personalizados

Generados voluntariamente por el programador mediante la instrucción throw cuando se violan reglas de negocio o precondiciones esenciales.

  • Intentar transferir más saldo del disponible.
  • Formularios con campos que no cumplen formatos válidos.
  • Objetos de error derivados de Error con nombres y mensajes específicos.

Tema 6.6.3

El Objeto Console

Métodos fundamentales para monitorizar el estado interno de nuestras aplicaciones: log(), assert() y clear().

📜 console.log()

Imprime cualquier valor primitivo o referencia a objetos en la consola estándar. Permite pasar múltiples argumentos separados por comas y utilizar cadenas con formato.

🛡️ console.assert(afirmación, mensaje)

Evalúa una expresión booleana. Si es falsa, escribe un mensaje de error en la consola. Si es verdadera, no produce ninguna salida, permitiendo pruebas de aserción no intrusivas.

🧼 console.clear()

Limpia completamente el búfer de salida de la consola activa, permitiendo empezar una nueva sesión de depuración con una vista limpia.

🔁 Demostración del Manual: Depurando el Bucle con Variable f

Analiza el siguiente código clásico extraído del manual donde se itera una variable f de 0 a 4 y se inspecciona su valor tras salir del bucle:

for (var f = 0; f < 5; f++) { console.log("Iteración f =", f); } console.log("Valor final de f =", f); // ¿Por qué f vale 5 aquí? console.assert(f === 4, "¡Fallo de aserción! f no es 4, vale:", f);
Terminal Virtual — Objeto Console Búfer listo
[Consola lista] Haz clic en un botón superior para emitir registros.

💡 Explicación Didáctica: ¿Por qué f vale 5 al terminar el bucle?

El bucle tiene la condición de permanencia f < 5 y la expresión de paso f++.

  1. En la 4ª vuelta, f tiene el valor 4. Como 4 < 5 es verdadero, el cuerpo se ejecuta.
  2. Al finalizar la iteración, se ejecuta f++, elevando el valor de f a 5.
  3. A continuación, el intérprete evalúa de nuevo la condición: 5 < 5 resulta falso.
  4. El bucle se interrumpe, pero la variable f declarada con var conserva su último valor asignado en el ámbito de la función: 5.
Tema 6.6.4

El Evento Global Error

Interceptación centralizada de errores no controlados a través del objeto window.

🌐 ¿Cómo funciona window.addEventListener('error', ...)?

Cuando ocurre una excepción en tiempo de ejecución que no es atrapada por un bloque try...catch, el navegador dispara el evento global error sobre el objeto window.

El objeto ErrorEvent recibido contiene información forense exhaustiva para diagnosticar o reportar la anomalía a un servidor de telemetría:

Propiedad Tipo Descripción Didáctica
message String Descripción textual legible del error (ej. "VariableNoExiste is not defined").
filename String Ruta absoluta o relativa del archivo JavaScript donde se originó el fallo.
lineno Number Número exacto de la línea del archivo donde la ejecución se quebró.
colno Number Número de la columna exacta dentro de la línea donde falló el analizador.
error Object Instancia nativa de Error (contiene el stack trace y constructor específico).

Tema 6.6.5

Control de Excepciones: try, catch y throw

Manejo defensivo de errores y lanzamiento de excepciones de negocio controladas.

🚀 La Sentencia throw

Permite interrumpir intencionalmente el flujo normal del programa y lanzar una excepción cuando una condición obligatoria no se satisface.

throw new Error("Mensaje descriptivo");

🛡️ Los Bloques try ... catch

try envuelve el bloque de código susceptible de fallar. Si se produce un error (o un throw), el control salta inmediatamente al bloque catch(error) sin que la aplicación se congele.

📦 Simulación del Libro: Gestión de Inventario con vendido()

En el manual se implementa una función de venta de artículos con un stock inicial de 5 unidades. Si la cantidad solicitada supera las existencias, se lanza una excepción con el texto exacto "Sin Existencia", la cual debe ser atrapada por try...catch.

var stockActual = 5; function vendido(unidades) { if (unidades > stockActual) { throw new Error("Sin Existencia"); } stockActual -= unidades; return stockActual; } // Invocación controlada: try { vendido(solicitud); } catch (err) { console.error("Captura:", err.message); }
